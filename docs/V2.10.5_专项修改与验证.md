# AutoFluent V2.10.5 — 变更、验收与剩余风险

## 基线与不变项
- 唯一基线：用户提供的 `AutoFluent_V2.10.4_Win64.zip`。未重做 Windows 原生前端或在线 Workbench 控制。
- 保留既有 Case/Data 配对、HDF5 原生面通量、端口净流量和总压降计算实现；11.9 专用数值后端未改动。
- 数据不会以配置的期望晶圆数或预期孔数冒充真实测量结果。

## 变更
1. `af_wafer_patches.py`：同 X 平面按共享网格边连接，保留多片独立面片；记录各面片面积、Y/Z 范围和质心。严格限制小断缝面片合并（微小缝隙、共同边方向、面积比例、唯一大面片证据）。前后壁采用双向对称投影覆盖率、面积比和厚度范围建立一对一配对。记录候选数、冲突 X、候选厚度/面积、每排晶圆和通道数及淘汰原因。支持投影重叠时使用配对实体中心为证据补充排判断，但不会用预期数量反推。
2. `af_adaptive_geometry.py`：自动模式先提取连通面片，再用真实重复面片质心推断层/排，减少腔室端壁与小支架对整体 Z 极值和面积直方图的污染。对真实 Z 投影重叠仍要求配置明确分界，不把晶圆实体归属与截面网格面归属混用。显式配置路径继续使用相同的壁面片/实体配对后端。
3. `af_adaptive_native.py`：挡板候选加入上下板面面积匹配、XZ 覆盖率及可读取的出口面区 Y 坐标证据。多个候选且出口距离没有明确区分时仍拒绝确定孔数；保存候选板位置、覆盖、面积和出口距离。孔洞以真实板面闭合开口为准，多积分片合并、板边通路/未归属流量分列；即便开口未验证仍保留已校验的完整截面通量。
4. `af_h5_offline.py`、`main_windows.go`、`af_report_v3.py`：文件配对、晶圆几何、报告保存状态分别存储/展示；几何失败时报告为“部分完成 · 晶圆几何待复核”；导出失败信息不再被后续几何状态覆盖，保留 JSON 和“仅重试 HTML 导出”。

## 仍未验收或不能保证
- 用户真实 6 寸 2.0 FFF `.cas.h5/.dat.h5` 未在这里执行；自动识别实际全网格壁面片数、384 片、380 通道、210 孔及逐通道数值没有确认。
- 2,601 万面工况下的内存峰值、运行时间、HDF5 多网格/混合单元兼容和 Windows GUI 实机交互未测试。
- 自动双排要求可分离的真实几何证据；物理 Z 投影重叠没有可靠通量分界时必须由配置指定，且近似范围须在报告中说明。
- 对极其复杂的非共形多面片、缺失网格边或非三角壁面仍可能拒绝识别；返回位置、候选证据和失败规则，而非伪造物理数值。
- 出口最近候选只有在实际出口区可读取且显著优于其他候选时才自动选择；两个合理挡板不区分时仍要求配置 `measurement.baffle_y_range_m`。

## 在 Windows 上复核真实保存解的只读命令
```powershell
$py = 'python'
$root = '这里填写解压后软件目录'
$case = '这里填写真实FFF.cas.h5路径'
$data = '这里填写真实FFF.dat.h5路径'
& $py "$root\worker\af_h5_offline.py" --file $data --case-file $case --output-dir "$root\reports\real_validation" --skip-pyfluent
```
检查导出的 JSON 中 `stage_statuses`、`metric_modules`、`first_full_analysis_blocker.diagnostics`、`port_flux`、`baffle` 和各层逐通道坐标。以上命令在本轮未运行真实 FFF。
