# AutoFluent V2.10.3：晶圆配对与部分结果发布专项修复

## 范围与主要改变

以 V2.10.2 为唯一源码基线，保留已通过的 11.9 专用计算路径及原生 H5 结果组/分段读取。本轮重点修普通对齐双排、交错双排及部分物理结果展示。没有修改在线工况发布和求解行为。

1. **真实壁面片识别**：按 X 法向、配置的 Y/X 范围先筛三角壁面；同一 X 平面按共享 YZ 投影顶点组成独立连通面片，允许不相交的两个晶圆排共享 X 坐标。对同一 X 处的明显重叠面片拒绝归属，不以数量预期修补几何。
2. **按厚度配对再分排**：使用真实物理厚度及前后面在 YZ 的投影对应关系建立一对一配对；同时兼容对齐和交错的相邻关系。孤立端部候选与疑似缺少前后面的阵列内候选分开处理。重叠 Z 排依据整片面片的独占 Z 边缘证据归属，无法唯一判定就明确报错。
3. **独立通量归属**：物理晶圆所属排与截面网格面所属区分开。Z 投影重叠要求配置 `overlap_split_z_m`；单张截面原生面互斥归属，正向、反向、净流量都核查闭合。不存在的中央旁路标记“不适用”；端部通量是外围子集，不二次加总。
4. **按模块发布**：共享读取 H5 后先完成端口、可用压力和候选挡板；再识别晶圆和片间。如果晶圆失败，仍交付已确认的端口/压力/挡板及 JSON、CSV、HTML，缺失的通道/旁路指标不补数字。记录 `stage`、`reason`、`modules`。
5. **用户界面状态**：Go 核心将 `partial_physical_metrics` 视为物理分析部分完成而非文件结构错误，Windows UI 显示“部分完成 · 晶圆壁面配对待复核”，并保留 HTML 打开入口。失败页展示实际端口和挡板数据及首个阻塞。

## 尚未完成的实机验收和风险

- 本环境没有用户真实的 26,011,622 面 FFF Case/Data；**未核对真实 2.0 模型的晶圆身份、384 片、380 通道、210 孔结果，也未测 32 GB Windows 内存峰值与耗时**。合成计数不是实测结论。
- 只支持已有后端的单相、三角面/四面体 CFF、晶圆法线 X 和气流 Y 的方向；复杂混合网格、缺失法向、非连通同片或无法分开的重合面需要后续支持。
- 显式几何配置的 `wafer_x_range_m` 是可选的、单位米；应由**当前真实模型测量**，不要复用测试用数组。`--check` 只校验 JSON 格式，不等于几何识别成功。
- 同 X 的两块实际重叠 YZ 面片、面片尺寸相近但多个合法配对、无可靠排边缘证据时，明确失败并给出坐标；不强行输出 CV。
- Windows GUI **完成交叉编译和 Go 单元测试，但没有 Windows 原生实机点击验收**。工况发布语义读回等仍属后续工作。

## 运行与复核

1. 解压整个 ZIP 后运行 `AutoFluent.exe`。在“保存解分析”选择 `.cas.h5` 或 `.dat.h5`；需要时用模型配置指定真实的 Y、X 搜索区与重叠 Z 分界。离线分析不依赖 Workbench。
2. 需独立复核时，使用已配置的 Python（含 numpy/h5py）：
   `python worker/af_h5_offline.py --file <保存解.dat.h5> --config <模型配置.json> --output-dir <输出目录> --skip-pyfluent`
3. 对同一组真实 Case/Data，先核验 `module_results` 和阻塞位置，再检查通道/孔的实际计数、逐项质量守恒、CSV/JSON/HTML 是否一致；最后核验 Windows 内存和 UI 行为。`--config ... --check` 只做配置格式检查。
