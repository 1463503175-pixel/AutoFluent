## 二、之前报告“看起来没改”的根本原因与修复

此前 11.9 成功分支返回 `.summary.html` 而不是新版报告，通用路径构造旧版 HTML 再覆盖，新报告失败时允许退回旧报告；因此此前交付说法错误。

本轮使三种路径分别调用 `render_reference_report`、`render_native_report`、`render_inspection_report`。物理计算与报告渲染相互独立；新版 HTML 无外链，包含深蓝头部、流量去向、真实坐标逐通道、挡板、压力、物理可信度、对比、下一轮建议和展开明细。11.9 专用统计所用 CSV/原始 HTML 仍保留，只把显示入口换成新报告。**新报告渲染失败时显式失败，不再显示旧 HTML 伪装成功**。

新增集成测试 `test_cli_unified_report_integration.py` 从合成 `.cas.h5/.dat.h5` 跑真实 CLI 入口，验证返回 `html_file` 位于 native_reports、HTML 含新章节、无原旧报告标题、JSON/CSV 与进度文件完整；再验证输入丢失后进度不虚报 99%。

## 三、H5 资源与危险边界

- Python Worker 支持原生多个连续编号数组块，审查 Face/Node ID 是否连续、缺失、重复；内存预算按写入配置设定（默认 6144 MiB，仅**估算值**）。
- 现有流程仍要求单个 `meshes`、三角面、四面体单元、当前几何坐标方向。对于其他真实数据结构**拒绝计算并提供结构诊断**，禁止用估算片间流量冒充真实结果。
- 原生面、节点、c0/c1 在 Python 内仍生成必需的大型 NumPy 数组；分块读取不代表真正 out-of-core。真实 Windows 32 GB 峰值必须在用户机器上运行才有结论。
- GUI 分析默认禁用无必要的可选 PyFluent 二次完整扫描，以免在首次通用引擎拒绝后额外占用内存；不修改 Fluent Case/Data、Workbench 或求解设置。
- 自动检查错误只读返回的 `h5_schema_*.json` 是较小结构样本，**不包含完整原始 H5 或物理统计**。这份文件可用于定位用户真实 2.0 无法读取的确切字段与分段布局，注意可能含少量几何数值。

## 四、进度百分比如何解释

- 所有被 GUI 纳入任务中心的运行任务共用左侧 0–100% 显示、状态和取消入口。
- 离线 H5 通过原子 JSON 快照显示节点、面拓扑、邻接、流量、几何、物理核验及输出等步骤；分块阶段显示真实 `completed/total`，百分比代表**加权阶段完成比例**，不是时间 ETA。
- WB／其他外部操作无法取得远端细分状态时显示「等待回执」，只显示已知的任务开始和结束，**不是精确的持续进度**；该部分不满足“每项操作都有细分可测百分比”的最终要求。
- 只完成 H5 结构诊断时，即使任务阶段完成为 100%，状态也明确写「物理指标未算出」；失败时保留实际阶段百分比，不显示伪造的 99%。
