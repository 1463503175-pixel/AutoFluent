# AutoFluent V2.9：六页面逻辑、按钮及问题整改审计

## 总结

默认操作路径改为 **保存解分析 → 模型对比**，无需 Workbench。只有需要操作现有 Fluent 时才进入 **连接工程 → 标准工况 → 求解与任务**。Workbench 手动端口不自动搜索，不调用 StartServer()，不新建 Solver。版本号升级是用于定位本轮实质功能、状态和布局修复。

已发现并修复的**确定性问题**：

1. 首页 `流程状态` 与主按钮共用 419px 附近的坐标，直接覆盖；已移到按钮下方，显示离线分析真实状态，不再展示无关的旧 gRPC 扫描状态。
2. 标准工况旧 JSON 模板与 `.set` 迁移共用坐标，出现说明、确认与编辑区拥挤；旧编辑/加载按钮继续隐藏，改为按 ①基准→②审核→③确认发布顺序布局。
3. Workbench 手动连接成功之后，Fluent 检查和设置/求解的独立 Python 子进程曾把 gRPC 无 TLS 警告和 JSON stdout 合并后直接 `json.Unmarshal`，产生**伪返回格式失败**；所有这些入口改为接收最后一条完整 JSON 回执。警告不算成功，必须有实际 JSON 回执。
4. WB 旧错误状态会在保存解页面顶部持续出现；现在标题状态按当前页面的离线/在线用途展示。
5. 高级 PyFluent 配置重复控件在主页面排版中占据大量空间；默认完全隐藏，正常 WB 工作链只显示端口、连接、端口帮助、完整诊断和必要时的依赖修复。
6. `同目录保存解清单` 曾覆盖“查看本次报告”的目标，导致清单被当成物理分析；现保持上次真实分析报告不变。
7. 过去“查看报告/浏览目录/比较模型”在没有前置输入时仍可能启用；增加可用性状态及文本提示。标准工况发布需审核在有效期内，且输入“发布工况”才可点。
8. 输出区长技术信息容易占满主界面；屏幕日志设上限，WB 单次完整认证尝试保存在 `wb_last_connection_diagnostic.txt`，可用专门按钮打开。
9. 调整按钮尺寸、内容页间距、全局日志区域、最小窗口布局、左侧激活项的背景映射。纯布局函数有多个窗口尺寸的自动化回归测试，**仍未在实际 Windows DPI / 不同屏幕上可视化验收**。

## 每页按钮的实际操作与产物

| 导航页 | 可见操作 | 前置条件 | 实际产物、结果 | 备注 |
|---|---|---|---|---|
| **工作台** | 选择 Case/Data 开始分析 | 已有 `.cas.h5` 与配套 `.dat.h5` | 切至分析页，尝试从真实 H5 产生 JSON/HTML/CSV | 默认主流程；新几何算法仅候选，未验收不许排名 |
| 工作台 | 连接现有 Workbench | 无 | 切至在线连接页 | **不自动**连接、找端口或启动服务 |
| **保存解分析** | 选择 H5 · 直接分析 | 保存解存在 | 自动配对/审计/原生通量计算或给出缺失原因、报告 | 优先真实 H5，绝不要求 Codex 报告 |
| 保存解分析 | 浏览同目录保存解 | 已选过一份 H5 | 同目录配对/库存清单 | 不等于完成流场统计，不覆盖物理报告 |
| 保存解分析 | 查看本次报告 | 当前会话成功生成受控 HTML | 打开最近一次 H5 分析 HTML | 没有报告时不可点击 |
| 保存解分析 | 导入历史报告（可选） | 有早期 HTML/JSON | 展开兼容区 | 纯兼容，不是正常分析前置条件 |
| 保存解分析·兼容区 | 选择历史报告、重新读取、整理历史报告 | 用户明确要利用历史文件 | 解析、汇总早期文件 | 不读取当前 Fluent 场数据 |
| **模型对比** | 选择模型 A、选择模型 B | 需要两个 H5 分析结果 | 填写各自分析 JSON | 连续进行两次 H5 分析也会自动填充 A/B |
| 模型对比 | 核对口径并比较 | A/B 均不为空 | 计算候选差异并检查可比性 | 无法证明收敛/同口径时不做正式排行 |
| **连接工程** | 输入 WB 端口、连接 Workbench | 当前 WB 的 `StartServer()` 端口 | PyWorkbench 连接、工程系统清单、随后自动只读探测 Fluent | 只连接手填端口；不要求 Fluent 先打开才连 WB |
| 连接工程 | 端口在哪里？ | 无 | 打开端口来源帮助 | 仅解释 WB 的 StartServer()，不是 Fluent Console |
| 连接工程 | 打开完整连接诊断 | 执行过 WB 连接操作 | 本地 TXT，含 Python/安全模式失败记录 | 无诊断时显示原因，不再把整段异常塞入界面 |
| 连接工程 | 配置 WB 连接依赖 | 检测到缺少 PyWorkbench；用户授权 | 在独立环境安装对应依赖 | 不变更系统 Python/Case |
| 连接工程 | 选择 Fluent 系统 | WB 有多个 Fluent 目标 | 只对用户选定的系统做只读验证 | 多系统不能猜测 |
| **标准工况** | 导出当前 .set | 已验证当前打开的 Fluent | 受控目录中生成原生 `.set` | 该文件只覆盖用户修改设置，不证明全部工况 |
| 标准工况 | 选择基准 .set | 源模型已通过程序导出 | 使用受控目录内的已导出设置作为来源 | 源模型导出成功后会自动填写路径 |
| 标准工况 | 只读工况摘要 | 当前 Fluent 已通过只读验证 | 原生汇总/Transcript | 不等于完整参数差异比对 |
| 标准工况 | ② 审核源与当前设置 | WB已验证且来源文件有效 | 发布前快照、计划及差异记录 | 不修改 Fluent |
| 标准工况 | ③ 发布并回读 | 计划有效、输入“发布工况”、再次确认 | 执行一次 `.set` 导入、导出回读核验 | 可能改变正在运行的 Fluent；不是完整物理工况认证 |
| **求解与任务** | 单批迭代数、确认后执行并记录残差 | 当前 Fluent 已验证、明确授权、Case 已备份 | 1–50 次迭代任务、Transcript/残差记录 | 不初始化、不自动重发；未知状态时停止后续自动执行 |
| 求解与任务 | 查看求解记录、刷新任务记录 | 有/无历史均可 | 最近任务回执、可读历史摘要 | 日志存在不等于已经收敛 |
| **全局** | 取消只读任务 | 正在执行可取消的本地只读任务 | 请求取消本地子进程 | **不承诺**远端 Fluent 命令已停止；发布和求解不允许误取消重发 |

## 当前版本未完成的物理/现场验收

- 你的 Windows/Workbench 2024 R2 **真实** `9935` 联机没有当前环境的可复查验收；代码错误修复不能替代真机证明。
- 当前程序 H5 自适应几何识别支持特定四面体与阵列，尚未证明对所有模型都能正确划分中央 X/Z 与外围旁路。
- `.set` 发布回读只能验证已导出的用户修改项；没有建立材料、默认设置、边界映射的完整统一清单。
- 自动求解限一次授权批次和残差记录，未完成联合质量守恒/CV/压降稳定性自动收敛认证。
- Windows GUI 未在本环境实际运行；新增的是布局计算、Go/Python 回归和 Win64 交叉编译，不应声称所有 DPI 下视觉已验收。
