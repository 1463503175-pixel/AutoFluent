# AutoFluent V2.10.2 — 本轮通用化修复与验收边界

## 用户报告的直接问题

2026-11-10 的 FFF 保存解诊断报告显示：**26,011,622 面触发 24,000,000 固定门槛**，随后可能出现 **3,036,000 壁面超过 2,300,000 固定门槛**，在这些前置条件下无法执行晶圆物理统计。

本版删除这两项固定数量拦截，改用 Case 元信息、数据类型、工作数组生命周期与可配置的内存预算预检。**没有上传真实 FFF.cas.h5 / FFF.dat.h5，故不能宣称该实际模型已算出。**

## 五组针对性改动

1. **资源与拓扑**：剔除固定 2400 万面/230 万壁面拦截，使用预算预估、32-bit 合法 ID 守卫；节点连接、c0/c1 有分块读取和溢出检测；单元质心及控制体残差改按块原位散射；X 方向晶圆候选与水平挡板候选均按真实壁面分块筛选；压力只抽取实际测站/集气腔选中单元。当前仍有全局 `conn`、`owner`、`flux`、`c1` 等 NumPy 数组，并非完整 out-of-core 实现。
2. **配对与路径**：新增共享只读配对器，优先用 Data `settings/Case File` 找到对应 Case；支持 `--case-file`/`--data-file` 指定快照；若同一 Case 对应多份 Data，要求用户选择，不能擅自选择；批量入口复用相同逻辑；删除通过路径名 `11.9` 触发专用算法的启发式。明确选择 `--prefer-11-9-reference` 时仍保留已验证专用脚本。
3. **交错排的 Z 投影重叠**：配置 `staggered` + 有效 `overlap_split_z_m` 可以启用分排。先根据 X 平面的真实壁面在独占 Z 区域的证据给每个站点赋行，再按每行配成真实晶圆和通道；之后对截面重叠区按指定 Z 分界唯一归属。对共享 X 平面的相交排或证据不足的站点明确拒绝计算，不能假装已经通用。
4. **部分物理结果独立交付**：当完整晶圆/挡板分析失败，新增仅端口的低内存原生面通量分析，不构造整套晶圆网格；端口/其他外边界的正向、反向、净流量及质量守恒独立发布，可用压力字段另算低速近似总压差；失败报告首页列出真实阻塞和各模块状态。即使端口成功，晶圆 CV/旁路也仍为“未取得”。报告是现有统一模板。
5. **对比与在线互斥**：片间的布局指纹扩展重叠分界/中央旁路；压降不再依赖晶圆截面一致，而由独立端口名/类型、压力定义、流量及守恒口径决定是否有带限定的对比值；挡板逐孔需要对应坐标一致；在线发布设置与求解共用按项目+系统+Fluent容器哈希的持久锁，未知远端状态不自动删除锁。

## 已执行的检查（仅合成/历史数据）

- Python：197 项通过；Go 全量测试与 `go vet` 通过。
- Windows x64 交叉编译成功，PE32+ Windows GUI 子系统，图标已嵌入。
- 稀疏 H5 **元数据**模拟了 26,011,622 个面和 3,036,000 壁面：512 MiB 预算正确拒绝并解释数量；6144 MiB 预算能通过旧硬上限位置并进入下一阶段（测试在读大数组前有意停止）。该 H5 是未存实际网格数据的稀疏元数据文件，**不是成功处理 2600 万面真实物理保存解**。
- 交错 Z 重叠反例验证 X 站点不重复、截面通量唯一分区；无法归属的共享 X 面拒绝计算。
- 带步数后缀的 Data/Case 引用配对和多快照歧义拦截通过。
- 独立端口测试：故意使用无法识别晶圆的有效小 H5，仍能从命令行获得入口/出口净通量和总压近似，报告包含首个失败原因。
- 保留 `af_native_11_9_reference.py` 原版哈希 `86ad611c21674a09912b34565deb9acaf4905a3cf27ea3feab391a329cffa790`，历史数值回归仍通过。

## 仍未完成及不能声称通过的事项

- **真实 FFF 2.0 保存解**：没有原始 `.cas.h5/.dat.h5`；其 HDF5 结构是否为多网格块、混合多边形面或多面体单元未知，仍可能被保守拒绝。需要真实错误和 `h5_schema` 后继续适配。
- **真正低常驻内存/out-of-core**：本版虽分块和减少中间对象，全量几何连接及通量数组仍驻留。32 GB Windows 峰值内存、运行耗时和数据集压缩开销未经过实测。
- **几何与物理**：所有轴向自适应、共享 X 平面重叠晶圆、所有挡板边缘情形、跨模型同一物理截面自动匹配、测压权重定义和求解收敛证据尚非普适可证。
- **GUI/在线**：现有六页与左侧进度沿用 V2.10.1；本版补充部分端口阶段进度，但未在 Windows 真机验收所有 DPI/按钮。工况已核对真实 zone/材料/模型开关的语义读回没有实现，现有 .set 哈希只证明文件一致。
- **报告**：模板化 HTML 从结构化结果生成，但真实 2.0 的逐图与现场报告仍未验证。

## 可重复验收命令

在程序根目录运行：
```
python -m pytest -q tests
go test ./...
go vet ./...
```
真实机器请在不修改原始 Fluent 保存解的前提下，单独选择 `.dat.h5` 让程序根据其内部 Case 引用配对。首次保留 `saved_reports` 对应报告 JSON、`h5_schema` 和 Windows 任务日志，核对计算成功/失败的第一阶段以及实际内存峰值。

**交付性质：针对性整改版，而非原计划十阶段全部验收完成版。**
